## Инструкция по выполнению и проверке

Все команды выполняются в терминале Linux. Для административных операций используется `sudo`.

### 1. Создание группы и второго пользователя

```bash
sudo groupadd developers
sudo useradd -m -s /bin/bash -G developers student2
sudo passwd student2
id student2
```

Проверка `id student2` должна показать, что пользователь состоит в группе `developers`.

### 2. Создание общего каталога

```bash
sudo mkdir /srv/shared
sudo chown root:developers /srv/shared
sudo chmod 2775 /srv/shared
ls -ld /srv/shared
```

Ключевой результат:

```text
drwxrwsr-x ... root developers ... /srv/shared
```

Цифра `2` в `2775` устанавливает `setgid` для каталога. Благодаря этому новые файлы внутри `/srv/shared` наследуют группу `developers`.

## Выполнение задания

### 1. Пользователь `student2` и группа `developers`

Создан отдельный пользователь `student2`, ему назначена оболочка `/bin/bash`, создан домашний каталог и добавлена дополнительная группа `developers`.

Это позволяет проверить групповую модель доступа Linux не теоретически, а на двух разных пользователях.

### 2. Права каталога `/srv/shared`

Для каталога установлены права `2775`:

- владелец `root` — `rwx`;
- группа `developers` — `rwx`;
- остальные пользователи — `r-x`;
- `setgid` обеспечивает наследование группы новыми файлами.

### 3. Проверка удаления чужого файла

От имени `student2` создаётся файл:

```bash
su - student2
echo test > /srv/shared/testfile.txt
exit
```

Затем другой пользователь пытается удалить его.

Главный вывод: **право на удаление файла определяется прежде всего правами на каталог**, в котором находится файл. Права самого файла отвечают за чтение, запись и выполнение его содержимого, но удаление — это изменение записи каталога.

### 4. Разница между `su` и `sudo`

`su` переключает текущую сессию на другого пользователя. При обычном `su` для перехода на `root` нужен пароль целевого пользователя, после чего последующие команды выполняются в новой пользовательской сессии.

`sudo` запускает конкретную команду с повышенными правами. Обычно используется пароль текущего пользователя, а разрешение определяется настройками `sudoers`. Такой подход удобнее для аудита и соответствует принципу минимально необходимых привилегий.

### 5. Почему прямой root-login обычно заблокирован

В Ubuntu аккаунт `root` по умолчанию обычно не используется для обычного интерактивного входа. Административные действия выполняются через `sudo`. Это снижает риск постоянной работы с максимальными правами и позволяет видеть, какой пользователь выполнил административную команду.

### 6. Настройка `~/.bashrc`

В `~/.bashrc` добавлены:

```bash
alias ll='ls -la'
alias update='sudo apt update && sudo apt upgrade -y'
export COURSE_ENV="pr-lab"
```

После открытия новой shell-сессии проверяется:

```bash
ll
echo $COURSE_ENV
```

Переменная выводит:

```text
pr-lab
```

Это подтверждает, что настройки автоматически применяются для новых интерактивных сессий.
